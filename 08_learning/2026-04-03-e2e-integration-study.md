# 정유 산업 E2E 프로세스 및 모듈 통합 
Date: 2026-04-03

## 1. 학습 배경
단순히 본인 모듈의 개발 리스트를 채우는 것을 넘어, 프로젝트의 성공적인 완성을 위해 **전사적 데이터 흐름(End-to-End)을** 완벽히 이해할 필요성을 느낌. 특히 SD(판매/물류)와 MM(구매/재고), PP(생산)가 맞물리는 접점을 집중적으로 분석함.

## 2. 핵심 학습 내용: SD-MM-PP 통합 흐름 (Pull 방식)

그동안 추상적으로 알고 있던 '물류센터 재고 보충' 프로세스를 구체적인 시스템 트랜잭션 단위로 이해함.

### [물류센터(Depot) 재고 보충 로직 분석]
물류센터 담당자가 사용하는 '주문 관리 대시보드'와 '보충 요청' 시스템의 상호작용을 파악함.

* **FC (Forecast/Demand)**: 특정 기간(예: 4월)의 고객 주문(S/O) 총합을 기반으로 한 수요량.
* **DR (Deployment Request)**: 물류센터의 가용 재고(ATP)가 부족할 때, 본사에 물량을 요청하는 단계. 
    - *Logic*: 팝업창을 통해 부족분(예: 400개) 입력 -> '보충 요청' 생성.
* **DO (Delivery Order) 전환**: 본사 관리자가 요청 내역을 검토하고 '승인' 버튼을 클릭하는 시점.
    - *System Action*: 승인과 동시에 본사 저장위치(SLoc)에서 물류센터 저장위치로 **재고 이동(Transfer Posting)** 처리.
    - *Accounting*: 이와 동시에 재고 자산의 위치 변경에 따른 FI 전표 자동 연동.


## 3. 모듈별 기술 구현 그라운드 룰 (Technical Ground Rules)

각 모듈이 비즈니스 요구사항을 충족하기 위해 선택한 기술적 구현 방식을 정리함.

| 모듈 | 주요 프로그램 목적 | 핵심 기술 (ABAP/Fiori) |
| :--- | :--- | :--- |
| **FI** | 실시간 전표 조회 및 환리스크 관리 | CDS View, 팝업(역분개), Maintenance View(확정환율 관리) |
| **MM** | 선적 기반 수입 물류 및 로스 정산 | In-transit GR 로직, BAPI(로스 전표 자동 생성) |
| **PP** | 변동 수율 반영 및 공정 추적 | 이원화 관리(계획-예측/실적-실측), Fiori Gantt Chart |
| **SD** | 거점별 수요 기반 Pull 물류 구현 | Search Help, 화면 이동, 자동 Stock Transfer 연동 |


## 4. 성찰 및 시사점

### [전체 프로세스 이해의 중요성]
* **모듈 간 단절 해소**: SD의 배송 오더가 MM의 재고 수량에 즉각 반영되고, 이것이 다시 PP의 생산 계획(PIR) 수립 근거가 되는 **Closed-loop** 구조를 명확히 이해함.
* **데이터 정합성**: 단순한 CRUD 기능 구현보다, "어떤 시점에 어떤 전표가 생성되어야 재무와 물류 데이터가 일치하는가"에 대한 설계 철학을 정립함.
* **도메인 지식의 힘**: 정유업의 특성인 '긴 리드타임'과 '연산품 구조'를 시스템 로직(선적 입고, 수율 차이 분석)으로 풀어내는 과정에서 SAP 컨설턴트로서의 역량이 성장함을 느낌.
