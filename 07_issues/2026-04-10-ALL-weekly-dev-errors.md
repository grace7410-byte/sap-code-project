## [Issue #3] 엔터 키 입력 시 이전 OK_CODE 잔상으로 인한 로직 반복 수행 오류 (MM) <a id="issue-3"></a>

### 1) 발생 현상
- 화면에서 엔터(Enter) 키 입력 시, 직전에 사용했던 `OK_CODE`가 메모리에 소거되지 않고 그대로 남아 있어 구매오더 아이템 확장 등의 특정 기능이 의도치 않게 중복 및 반복 수행되는 잔상 현상 발생.

### 2) 해결 방안 및 조치
- PAI 단의 `USER_COMMAND_0100` 모듈 내에서 현재 `ok_code` 값을 로컬 변수에 안전하게 대피(보관)시킨 직후, 글로벌 전역 변수인 원본 `ok_code`를 `CLEAR` 처리하여 엔터 입력에 의한 이벤트 중복 실행 현상을 근본적으로 제거 완료.

---

## [Issue #4] ALV 제어 기능 작동 시 일련번호(Item Number) 동기화 오류 (MM) <a id="issue-4"></a>

### 1) 발생 현상
- ALV Grid에서 행 추가, 행 삭제, 행 복사 버튼을 클릭했을 때 내부적으로 `set_item_number` 채번 로직은 수행되나, 정작 화면(UI)상에는 변경 전 번호가 그대로 유지되거나 공백으로 밀려 출력되는 갱신 불일치 현상 발생.

### 2) 해결 방안 및 조치
- ALV 커스텀 이벤트 핸들러 클래스(`lcl_event_handler`)의 `on_after_user_command` 이벤트를 캡처 및 활용하여, 사용자의 행 제어 동작 직후 인터페이스 레이아웃 레벨에서 `set_item_number` 로직이 강제로 즉시 재실행되도록 이벤트 처리 우선순위를 수동 조정하여 화면 정합성 확보 완료.

---

## [Issue #5] Subroutine 내 전역 변수 직접 접근으로 인한 코드 의존성 및 사이드 이펙트 발생 (PP) <a id="issue-5"></a>

### 1) 발생 현상
- 서브루틴(`Subroutine`) 내부에서 프로그램 전역 변수(`Global Variable`)에 직접 접근하여 가공하도록 설계되어, 핵심 비즈니스 로직에 변경 사항이 없음에도 불구하고 단순히 전역 변수를 추가하거나 변수명을 수정할 때 전체 소스 코드가 손상되거나 연쇄적으로 영향을 받는 불안정한 현상 발생.

### 2) 해결 방안 및 조치
- 서브루틴 구문 호출 시 필요한 값을 `USING` 이나 `CHANGING` 서명(Interface)을 통해 명확하게 넘겨주도록 아키텍처를 전면 변경함. 내부 로직과 외부 변수의 결합도를 낮추고 인터페이스를 명확히 정의함으로써 변수 수정 시의 사이드 이펙트를 차단하고 로직의 독립성 확보 완료.

---

## [Issue #6] Function Module 파라미터 정의 시 Default Value 구문 에러 (FI) <a id="issue-6"></a>

### 1) 발생 현상
- Function Module의 Import 파라미터 정의 부분에서 Default value에 통화필드 기본값을 KRW로 입력하는 과정에서 에러 발생.

### 2) 해결 방안 및 조치
- Default value에 일반 텍스트 형태가 아닌 작은따옴표를 양쪽에 붙인 'KRW'를 입력하여 오류 조치 완료.

---

## [Issue #7] PARAMETER 미입력 시 SELECT 구문 조건 검색 불가 오류 (FI) <a id="issue-7"></a>

### 1) 발생 현상
- 화면 SELECTION-SCREEN 설계 중 조회 조건에 위치한 전표 유형(`PARAMETER`) 필드를 사용자가 공백으로 두고 조회할 경우, 데이터 조건 매핑이 정상적으로 수행되지 않아 전체 조회가 불가능하거나 에러가 발생하는 현상 발생.

### 2) 해결 방안 및 조치
- 단일 입력 파라미터의 한계를 보완하기 위해 전표 유형을 `SELECT-OPTIONS`와 유사한 내부 `RANGE` 변수로 전환 선언한 뒤, 사용자가 입력한 값을 동적으로 캡처하여 데이터베이스 `SELECT` 구문의 `WHERE` 조건절에서 `EQ` 대신 `IN` 연산자를 사용하도록 변경함으로써 공백 및 다중 조건 처리 오류 조치 완료.

---

## [Issue #8] 다중 필터 및 조회 조건 동시 만족 데이터 호출 에러 (FI) <a id="issue-8"></a>

### 1) 발생 현상
- 전표 카테고리 이동 탭(전체/구매/판매/생산 라디오버튼) 기능과 상단의 기본 화면 조회 조건을 동시에 바인딩하여 만족하는 데이터를 화면 인터페이스에 파싱하는 과정에서 데이터 누락 및 덤프 에러 발생.

### 2) 해결 방안 및 조치
- 라디오버튼의 선택 상태값에 따라 명확한 내부 구분자(구분 플래그)를 할당하고, 이를 서브루틴(`Subroutine`)의 인터페이스 파라미터로 정밀하게 념겨주어 해당 범주(구매/판매/생산/전체) 동적 쿼리가 분기문을 타고 올바르게 조회되도록 아키텍처 제어 조치 완료.

---

## [Issue #9] SAP Tree Control Node Key 중복 지정에 따른 덤프 오류 (SD) <a id="issue-9"></a>

### 1) 발생 현상
- 판매오더 현황을 계층형 Tree 구조 화면으로 출력하는 과정에서, 각 노드의 고유 식별자인 `node_key` 값에 판매오더 아이템 테이블의 `vbeln`(판매문서번호) 필드를 직접 대입함에 따라 다중 아이템을 가진 오더의 경우 동일한 오더 번호가 중복 생성되어 시스템 내에서 키 충돌 및 에러가 발생하는 현상 발생.

### 2) 해결 방안 및 조치
- 상위 노드의 고유성을 확보하기 위해 중복 데이터가 발생하는 아이템 테이블 참조를 지양하고, 고유한 단일 키 값을 보장하는 판매오더 헤더 테이블의 `vbeln` 필드를 `node_key` 생성 소스로 변경 할당함으로써 트리 구조 렌더링 시 발생하는 키 중복 구문 오류 조치 완료.
