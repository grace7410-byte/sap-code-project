# [Anvil Integrated Issue Log] 2026-06-12 전사 통합 개발 이슈 모음집

목적: 전사 모듈(MM/SD/PP/FI/CO) 구현 과정에서 발생한 모든 기술적 오류, 시스템 버그 및 트러블슈팅 내역을 한 번에 통합 관리함.
1) 발생 현상, 2) 해결 방안 및 조치 순으로 기재.

## [Issue #1] ALV 집계 행(SUBTOTAL/TOTAL) 선택 삭제 시 덤프 에러(DUMP ERROR) 발생 결함 (PP/SD) <a id="issue-1"></a>

### 1) 발생 현상
ALV 툴바 내 삭제 버튼 클릭 이벤트 처리 중, 엔드유저가 집계용 소계(SUBTOTAL) 또는 합계(TOTAL) 행을 선택한 상태에서 삭제 요청 커맨드를 실행할 경우 물리적 테이블 데이터 포인터 불일치로 인해 시스템 덤프 에러(DUMP ERROR)가 유발되는 결함이 발생하였다.

### 2) 해결 방안 및 조치
삭제 이벤트 핸들러 로직 상단에 선택된 행의 데이터 타입을 검증하는 방어 코드를 추가하였다. 소계 및 합계 라인은 실제 DB/내부 테이블 레코드가 아니므로, 해당 행이 클릭 및 선택되었을 때는 삭제 프로세스가 가동되지 않고 예외 처리되도록 이벤트 실행 권한을 제어 및 제한하였다.

## [Issue #2] PLAN/FINN 원가 데이터 조건별 예외 및 MM 모듈 정합성 오류 결함 (CO) <a id="issue-2"></a>

### 1) 발생 현상
- PLAN(계획) 데이터와 FINN(실적) 데이터의 존재 여부 및 모듈 간 데이터 정합성에 따라 다음과 같은 예외 버그가 다수 발생하였다.
  1. PLAN과 FINN 데이터 중 한쪽만 존재할 경우 예외 처리 미비 문제 발생
  2. CO 모듈에는 레코드가 존재하지 않으나 MM 모듈에만 존재할 경우 데이터 불일치 발생
  3. PLAN 데이터가 단순 계획 정보임에도 불구하고 실제 원가 집계 로직에 오반영되는 현상 발생

### 2) 해결 방안 및 조치
- PLAN과 FINN 데이터가 동시 존재 시 이를 명확히 분별하여 실 원가 반영 로직에 구별 적용하도록 수정하였다.
- DB Table 저장 전 단계에서 MM 모듈 데이터를 전수 검증 및 조회하는 방어 코드를 작성하여 모듈 간 데이터 불일치 이슈를 차단하였다.

## [Issue #3] CDS View 실시간 환율 데이터 참조 고정 결함 (MM) <a id="issue-3"></a>

### 1) 발생 현상
- 테스트 전표 생성 시, 당일 날짜의 변동 환율 데이터가 CDS View 및 화면 상에 실시간으로 반영되지 않고 과거 환율 값(1528.6)으로 고정되어 출력되는 현상이 발생하였다.
- 분석 결과 환율 마스터 테이블 내 동일 날짜 데이터 중복 생성 및 문서 생성일 기준 참조 시점 불일치가 원인으로 파악되었다.

### 2) 해결 방안 및 조치
- 중복 등록된 마스터 레코드를 정리하고 정상적인 참조 시점 관계를 재확인하였다. 재검증 테스트를 통해 당일 환율 데이터가 정확히 바인딩됨을 확인하고 예외 데이터를 정돈하였다.

## [Issue #4] 입고-송장검증 프로그램 간 원화 환산 연산 오차로 인한 차대변 금액 불일치 결함 (MM) <a id="issue-4"></a>

### 1) 발생 현상
- 입고 관리 프로그램과 송장 검증 프로그램 간 동일 자재(MM12, MM14 구역)를 조회했을 때 원화 산출 금액이 상이하게 표기되어 전표의 차대변 합계가 일치하지 않는 오류가 발생하였다.
- 송장 검증 프로그램은 `[외화 총 금액 * 당일 환율]`로 정상 연산한 반면, 입고 관리 프로그램은 단가 및 수량 단위의 개별 나누기/곱하기 과정에서 소수점 반올림이 중복 적용되어 단수 차이가 발생한 것으로 확인되었다.

### 2) 해결 방안 및 조치
- 검증이 완료된 송장 검증 프로그램의 연산 공식을 전사 표준으로 채택하였다. 입고 관리 프로그램 내부의 원화 환산 로직을 `[외화 총 금액 * 환율]` 방식으로 일괄 통일하여 소수점 연산 오류에 따른 차대변 금액 불일치 문제를 해결하였다.

## [Issue #5] Fiori UI 상 복수 OData 엔티티 비동기 수신 순서 불일치 결함 (PP) <a id="issue-5"></a>

### 1) 발생 현상
- Fiori 생산계획 CRUD 앱(`ZPB1PP01`) 개발 도중, 화면 레이아웃 구성 및 헤더/아이템 렌더링에 필요한 복수의 OData 엔티티 데이터를 한 번에 가져오는 과정에서 호출 순서 및 수신 완료 시점이 어긋나 UI 데이터 바인딩 오류가 발생함.

### 2) 해결 방안 및 조치
- JavaScript 컨트롤러 내에 `Promise Wrapper` 패턴을 구현하여 복수의 OData 데이터 조회 요청을 비동기 구조로 안전하게 래핑 및 컨트롤함. 데이터 응답 완료 후 UI 렌더링이 순차 진행되도록 흐름을 보완함.

## [Issue #6] Fiori OData 날짜 필드 초기값(`00000000`) 파싱 에러 결함 (FI) <a id="issue-6"></a>

### 1) 발생 현상
- Fiori AR 반제 프로그램(`zpb1fi10`) 데이터 조회 시, 백엔드 Table/CDS 내 날짜 필드 값이 미입력 상태(`00000000`)인 레코드를 OData 서비스가 읽어오는 과정에서 데이터 타입 래핑 에러가 발생함.

### 2) 해결 방안 및 조치
- SAP Gateway Service Builder(`SEGW`) 환경으로 진입하여 해당 엔티티 세트 내 날짜 타입 필드의 `Nullable` 속성을 활성화함. 빈 값 형태의 날짜 수신 시에도 예외 없이 렌더링되도록 수정함.

## [Issue #7] Screen Flow Logic 내 전기키(BSCHL) 수동 수정값 덮어쓰기 결함 (FI) <a id="issue-7"></a>

### 1) 발생 현상
- 전표 수동 생성 프로그램(`SAPMZB1FI0001`)에서 계정유형 및 차/대변 선택에 따라 전기키가 자동 제안된 후, 사용자가 해당 전기키 값을 다른 값으로 수동 변경하더라도 화면 재검증 과정에서 자동 제안 구문을 다시 실행하여 사용자의 수정값이 무효화되는 현상이 발생함.

### 2) 해결 방안 및 조치
- 스크린 PAI 영역의 `CHAIN-ENDCHAIN` 블록 내에서 `BSCHL`(전기키) 필드를 제외 처리함. 사용자가 전기키를 직접 수정했을 때는 자동 제안 모듈을 건너뛰도록 흐름을 보완하여 수정값이 정상 유지되도록 해결함.
