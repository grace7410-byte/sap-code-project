## 1. 진행 내역
- **04.08**: 공급업체 입력 시(서치헬프 사용), 구매오더 헤더 정보에 해당 공급업체에 맞는 구매 정보를 매핑하여 인풋/아웃풋 필드로 활성화하였다. 이 때, 펑션모듈을 사용하여 도메인 텍스트 값도 함께 조회되도록 설정하였다.
- **04.09**: 구매오더 아이템 정보를 생성할 수 있도록 Edit 모드의 ALV 를 구현하였다. ‘최적화 데이터 불러오기‘ 버튼 클릭 시 구매 최적화 조건(인포 레코드) 데이터를 가져와 아이템에 추가할 수 있도록 조치하였다.
- **04.10**: 사용자 입력 데이터 검증 로직 및 예외 처리를 구성하였으며, CDS View 를 사용하여 환율 적용된 단가 데이터를 호출하였다. 이는 아이템 데이터 추가 시 실시간으로 반영되도록 구현하였다.

### 📌 차후 추가 기능 및 프로그램
- 원재료 중심의 PO 설계에서 운송비 별도 정산을 위한 서비스 구매오더(Service PO) 기능을 지원하도록 KNTTP(계정), PACKNO(서비스번호) 필드 제어 로직을 추가할 예정이다.
- 서비스 PO 구현 시, 운송업체의 송장 처리를 고려하여 서비스 엔트리 시트 데이터가 ALV 에서 생성된 PO 와 유기적으로 연결되도록 인터페이스를 확장할 계획이다.
- 확장된 구매오더 생성 프로그램 개발이 마무리되면 구매오더 결재(승인) 프로그램을 구현할 예정이다.

## 2. 발생한 기술적 오류 및 조치
* **오류 1**: 엔터 키 입력 시, 이전 OK_CODE 가 메모리에 남아 특정 기능(구매오더 아이템 확장 등)이 의도치 않게 반복 수행되는 잔상 현상 발생.
* **조치 1**: USER_COMMAND_0100 모듈 내에서 ok_code를 로컬 변수에 보관한 즉시 원본을 CLEAR 처리하여 엔터 입력에 의한 이벤트 중복 실행 제거 완료.
* **오류 2**: ALV 행 추가/삭제/복사 버튼 클릭 시, set_item_number 로직을 통하나 화면상에는 변경 전 번호가 그대로 유지되거나 공백이 되는 현상 발생.
* **조치 2**: lcl_event_handler 의 on_after_user_command 이벤트를 활용하여 동작 직후 set_item_number 가 강제로 실행되도록 이벤트 우선순위 조정 완료.
