## 1. 진행 내역

**[ SAPMZSD0003 ]** 판매가 결정 프로그램 *(구현완료)*

* 판매가 결정 세션에 실질적으로 사용할 마스터 가격 데이터를 시스템으로 불러오기 위하여 유효시작일 입력 필드에 날짜를 입력하도록 구현하였다. 이때 입력한 날짜와 완벽히 매칭되는 데이터가 존재할 경우에는 이를 그대로 화면에 조회하고, 만약 일치하는 데이터가 없을 때에는 시스템 내의 가장 최신 데이터를 추적하여 조회하거나 아예 신규 가격을 생성할 수 있도록 로직을 설계하였다.
* 완전히 새로운 판매가를 신규 생성하는 프로세스일 경우에는 제품별로 징수할 마진율 퍼센트를 유저로부터 직접 입력받도록 처리하였다. 이를 기반으로 해당 날짜의 제품별 MOPS 수치와 당일 환율, 그리고 유저가 입력한 마진율 퍼센트를 다각도로 연산하여 기본가격(PR00) 구성을 구성하기 위한 프리미엄가를 자동으로 계산하도록 아키텍처를 구축하였다.
* 마진율 기본값 박스 내부 영역에는 '오늘의 시장 지표 확인' 버튼을 배치해 주었으며, 이 버튼을 클릭하면 당일 날짜 기준의 제품별 MOPS 데이터를 실시간으로 시각화하여 검증할 수 있도록 하였다. 만약 오늘 자 시장 지표 데이터가 아직 인터페이스 테이블에 적재되지 않았을 경우에는 배치 엔진 상 가장 최신의 데이터를 인터페이스 화면에 띄우도록 예외 처리를 수행하였다.
* ALV 레이아웃 내에서 자재코드 필드에 핫스팟(Hotspot) 이벤트를 연결하였으며, 유저가 특정 자재코드를 마우스로 클릭하면 화면 우측 영역에서 BBL(배럴)당 최종 판매가를 직관적으로 검증할 수 있도록 구현함과 동시에 연관된 세금 구성 금액까지 한 화면에 병렬 표시하도록 처리하였다.
* 정유 제품에 대한 세부 금액 산정 규격은 정부의 세제 정책에 의해 수시로 변동되므로, UI 상단 세금 안내 박스 섹션 내에 '정부 고시가 확인' 버튼을 설계해 주었다. 해당 웹 컴포넌트 버튼을 클릭하면 외부 공식 정부 고시 사이트의 웹링크(Web Link)로 부드럽게 세션이 이동하여 실시간 정책을 모니터링할 수 있도록 연동하였다.
* 메인 화면의 제일 하단부 영역에는 각 제품별로 최근 5일간의 BBL당 최종 판매가 추이 데이터를 비주얼 차트(Chart) 오브젝트로 동적 바인딩하여 렌더링함으로써, 현업 담당자가 판매가의 정기적인 변화량을 한눈에 식별하고 파악할 수 있게 배치하였다.
* 판매가 결정 로직을 모두 검토한 후 최종 저장 버튼을 누르는 순간, 인스턴스 버퍼 데이터들이 SD0004 물리 데이터베이스 테이블에 커밋(Commit)되어 그날의 기준 판매가격이 최종적으로 확정 및 정해지도록 빌드하였다.

* 표준 Fiori 가이드라인에 기반한 Wizard 컴포넌트를 레이아웃에 탑재하여, 현업 유저가 단계별 시퀀스 프로세스를 순차적으로 진행한 뒤 최종 검토 세션을 거쳐 에러가 없을 때 최종 판매오더(Sales Order) 전표가 실시간으로 자동 빌드 및 생성되도록 아키텍처를 구현하고 있다.

* 유저가 주문 프로세스 도중 판매 대상 제품과 수량을 마우스로 가변 및 선택하였을 때, 그 선택 조건에 매칭되는 실시간 산정 가격 데이터가 화면 최상단 전용 대시보드 영역에 즉각적으로 바인딩되어 실시간으로 가격 변동 추이가 바로바로 화면에 반영되도록 로직을 처리하였다.

## 2. 발생한 기술적 오류 및 조치

- **오류 10**: ABAP ALV 화면에서 금액 데이터 필드의 통화 속성이 명확히 KRW(원화)로 바인딩되어 있음에도 불구하고, 내부 버퍼 오류로 인해 출력 화면상에서 금액 데이터 후미에 `.00` 소수점이 계속 강제로 붙어서 가시성이 심각하게 훼손되는 현상이 발생하였다.
- **조치 10**: 인터페이스 테이블에서 데이터를 화면으로 스트리밍하기 직전, 내부 원화 포맷 제어용 표준 함수인 `BAPI_CURRENCY_CONV_TO_INTERNAL`을 소스 코드 단에서 호출하도록 구조를 수정하였으며, 이를 통해 시스템 내부의 불필요한 소수점 명세를 강제로 제거하여 원화 규격에 맞는 깔끔한 정수 형태로 출력되도록 해결하였다.

- **오류 11**: 인풋 필드 영역에 사용자가 수치를 입력한 후 엔터(Enter) 키를 누르면 화면의 PAI(Process After Input) 로직을 정상적으로 타도록 구성하였으나, 런타임 환경에서 시스템이 현재 이벤트를 발생시킨 인풋창이 유효시작일 필드인지 혹은 마진율 퍼센트 입력 필드인지 고유의 필드 ID를 인식 및 구분하지 못하는 결함이 식별되었다.
- **조치 11**: PAI 트랜잭션 초입 영역에 SAP GUI 스크린 제어 구문인 `GET CURSOR` 명령어를 명시적으로 구현하였으며, 런타임 시점에 사용자의 커서가 위치한 물리 필드의 고유 테크니컬 네임 값을 실시간으로 변수에 캐치 및 인터셉트하도록 소스를 수정하여 PAI 세션 내부에서 각 필드별 프로세스를 정밀하게 분기 및 구분하도록 처리하였다.

- **오류 12**: Fiori UI 애플리케이션 화면에서 유저가 a제품 수량 1개와 b제품 수량 1개를 각각 마우스로 가변 선택하였을 때에는 상단 대시보드의 통합 합계 금액 필드에 정상적으로 합산 연산되어 렌더링되었으나, b제품의 수량을 1개에서 0개로 하향 조정하여 변경하는 예외적인 케이스가 발생하였을 때에는 상단 합계 가격 데이터가 차감되지 않고 기존 가격을 그대로 유지하고 있는 데이터 왜곡 오류 현상이 발생하였다.
- **조치 12**: Fiori 뷰 레이어 단에 인라인 형태로 산만하게 분산되어 있던 가격 계산 수식 로직들을 자바스크립트 `controller.js` 단의 독립적인 커스텀 함수(Function) 구조로 전면 격리 및 추출하였다. 이후 UI의 StepInput 컴포넌트 상에서 수량 변경 이벤트(`change`)가 감지되어 트리거될 때마다, 전체 타깃 제품 6개에 대한 실시간 개별 금액 계산을 백그라운드에서 매번 전수 재실행한 뒤 이를 마스터 변수에 통째로 재합산하여 덮어쓰는 동적 루프 방식으로 아키텍처를 개편하여 연산 결함을 완벽하게 해결하였다.
