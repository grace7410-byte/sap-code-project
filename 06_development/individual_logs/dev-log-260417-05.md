## 1. 진행 내역
- **04.13**: 생산관련 Function Module을 생성하다 판매관련 Function Module을 먼저 생성하는 것으로 변경하였다. 판매제품의 출고 전표, 송장(빌링)청구 전표, 입금 전표를 기반으로 Function Module을 만들기 시작하여 처음으로 출고 전표의 자동생성 Function Module 개발에 착수하였다.
- **04.14**: 판매단계의 판매제품 출고 시 전표가 자동으로 생성되는 것을 구상하였다. 차변에 매출원가, 대변에 여러 제품이 적히며 차변과 대변이 1:N 구조가 된다는 것을 인지하고, 기존에 1:1 로 만들던 Function Module을 수정하였다. 이후 금액을 SD 에서 직접 가져오지 않고 CO 에서 매출원가 금액을 가져와야 한다는 것을 알게 되어 그 부분을 함께 반영하였다.
- **04.15**: 조원들과 상의한 결과 자동 전표 생성을 위한 Function Module을 각 전표별로 만들지 않고 각 단계별로 통합적으로 만들게 되었으며, 이에 구매단계, 생산단계, 판매단계로 나눠 생성하기로 결정하였다.
- **04.16**: 중간발표 전 미팅을 통해 Function Module도 중요하지만 1차 마감을 위한 프로그램 완성을 먼저 준비하는 것이 좋을 것 같다는 피드백을 반영하여, 판매 전표 관리(CRU) 프로그램을 생성하였다.
- **04.17**: 전체 전표 대시보드 프로그램 [ZRB1FI0001](../../04_design/03_program_specification_260429.md#index06) 에서 특정 행 선택 시, 해당 데이터를 유지한 채 판매 전표 관리 프로그램의 Selection Screen 으로 자동 매핑되며 해당 인풋 필드가 비활성화되도록 연동 로직을 구축하였다. 또한 수동전표 생성 화면에서, 기존에는 헤더와 아이템 전표가 상/하 배치되어 있었으나 이를 우측 ALV와 좌측 헤더/아이템 인풋창 구조로 재배치하였다.

### 📌 차후 추가 기능
- 헤더 전표 수동 생성 시 참조문서번호 입력 후 전표 확정 버튼을 누르면, 그에 맞는 SD 테이블 데이터가 ALV에 띄워지고 동시에 아이템 전표의 인풋창들이 활성화되어 입력 가능하도록 구현 예정
- 참조문서번호에 맞는 출고, 매출, 입금의 헤더와 아이템 테이블을 DB View 로 구성하여 우측 ALV에 헤더와 아이템이 한 번에 보이도록 추가 구현 예정
- 각 참조문서번호에 맞게 동적으로 ALV의 컬럼명이 바뀌도록 로직 추가 예정
- 추후 역분개까지 고려하여 프로그램 마무리 예정
