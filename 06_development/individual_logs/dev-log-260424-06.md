## 1. 진행 내역
- MM에서 발생하는 전표 시점(선적입고, 송장, 플랜트입고)과 참조문서번호를 조회조건으로 구성하였다.
- 자재이동문서 헤더 + 아이템, 송장 헤더+아이템 총 2개의 CDS VIEW로 구성하였고, 각 CDS VIEW에서 당시의 환율을 FI 테이블에서 갖고 올 수 있도록 구성하였다(left outer join 사용).
- 조회조건을 입력 후 조회버튼을 누르면 ALV로 자재이동문서, 송장데이터를 띄우며 참조할 수 있게 구성하였다(레퍼런스 테이블). 이때, 필드 구성은 FI에서 필요한 필드만을 조합해서 가지고 왔다.
- 조회버튼을 누르면 FI 전표 헤더에 들어갈 데이터가 비활성화 되어있는 INPUT 필드에 들어오고, 헤더내역만 활성화된다. 헤더내역을 작성하고 저장 버튼을 누르면 다시 비활성화 처리되고, 버튼 TEXT는 변경으로 바뀐다.
- 레퍼런스 테이블에 있는 행을 더블클릭 시 하단에 있는 전표 아이템 ALV에 자동으로 차변/대변(2줄이 한 세트)되도록 구성하였다. 이때, 아이템 내역을 제외하고 레퍼런스 테이블에 있는 데이터도 자동으로 전표 아이템 테이블에 매핑되며 비활성화 처리된다. 차/대변 금액이 같이 띄워지며 비교 가능하도록 구성하였다.
- ALV에 있는 행을 선택하고, `<행삭제>` TOOLBAR 버튼 클릭 시, 삭제된다.
- ALV에 `<최종데이터예시>` TOOLBAR 버튼 클릭 시, popup이 띄워지며 DB에 반영되는 데이터의 예시를 볼 수 있도록 alv로 구성하였다.
- popup에 있는 alv에는 collect 함수를 써서 키값이 동일한 데이터는 금액이 합산되어 보이도록 구성하였다.

## 2. 발생한 기술적 오류 및 조치
- **오류 1**: Input 필드 활성화/비활성화, 동적 버튼 text가 동시에 일어나면서 원하는 시점에 활성화/비활성화 처리 불가.
- **조치 1**: pbo에서 두 위치에서 활성화/비활성화 처리하던 것을 하나의 위치에서 분기처리로 구성하여 해결하였음.
- **오류 2**: Collect 함수 사용 시 환율까지 합산되어 나오는 오류 발생.
- **조치 2**: alv에 띄울 데이터를 다 구성한 뒤 loop를 돌면서 환율 값 적용시켜주어 해결하였음.
