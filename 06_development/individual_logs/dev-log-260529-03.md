    * **덤프 에러 방지:** 원화 금액 변수가 가진 물리적 최대 자릿수 제한 속성으로 인하여 시스템 쇼크가 올 수 있는 프로그램 덤프(`Dump`)를 미연에 방지하고자, 현재 환율 데이터를 기준으로 입력이 허용되는 기술적 최대 USD 금액 한도를 역산한 뒤 사용자가 한도 초과 금액을 기입할 시 사전에 원천 차단하도록 안전장치를 적용하였다.

    * 기존에 `CALL SCREEN` 구문 바로 앞에서 임시 플래그 변수(`gv_first_check`)에 의존하여 단 한 번만 일시적으로 가동되던 전체 데이터 조회 로직 아키텍처를 `get_po_data`라는 하나의 가시성 높은 서브루틴 팩으로 전면 묶어 정돈하였다. 이러한 모듈화 구조 변경을 통해 메인 화면이 최초 로드되는 시점(`MODULE status_0100 OUTPUT`)에 선행 실행되고, 이후 사용자가 데이터를 저장(`FORM save_volm_data`)한 직후 타이밍에 백그라운드에서 자동으로 재차 호출되도록 흐름을 제어함으로써 화면 ALV 데이터가 실시간으로 완벽하게 동기화되도록 처리하였다.
    * 추가적으로 저장이 성공 완료되면 방금 현업 유저가 실시간으로 수정한 구매오더 데이터 행을 화면 전체 ALV 그리드 상에서 가장 쉽고 빠르게 서칭할 수 있도록, 해당 타깃 행의 컬러 필드 속성(`col_col = 1`)을 동적으로 강조 표기해 주는 예외 처리 디자인 코드를 내부에 정교하게 반영하였다.
    * **저장 중복 차단:** 사용자가 저장 프로세스를 수행할 때, 이미 동일한 마스터 측정 번호와 항목 번호가 물리 데이터베이스 테이블(`ztb1mm0020`) 내에 선행 적재되어 있는지 `SELECT` 사전 검증을 수행하도록 하였다. 만약 중복 레코드가 검색될 경우에는 트랜잭션 충돌로 판단하여 즉각 `ROLLBACK WORK` 처리함과 동시에 에러 메시지를 호출하여 저장을 차단하였다. 저장이 정상 완료되면 공용 타임스탬프 관리 펑션(`ZFB1CM0001`)을 명시적으로 태워 마스터 시스템 정보를 `MODIFY` 변경 적용한 뒤 `COMMIT WORK`를 수행하도록 유도하였고, 화면 인스턴스 초기화 직후 `set_new_ok_code('REFRESH')` 구문을 활용하여 화면을 강제로 새로고침 연동하였다.
    * 고유 마스터 키값인 측정번호(`ZMSNO`) 데이터 속성을 사용자가 수동으로 임의 편집하거나 오수정했을 때 발생할 수 있는 데이터 크래시 방어 로직을 견고하게 구축하였다. 사용자가 입력 필드에 기입한 번호 문자열에서 날짜 구간 세그먼트를 잘라낸 뒤, 해당 일자 기준으로 DB에 적재된 기존 레코드들의 맥스 일련번호 수치를 서칭하도록 처리하였다. 그리하여 동일한 참조 구매오더 건일 경우에는 기존 일련번호(`SEQ`)를 정합성 있게 유지하도록 분기하고, 아예 새로운 오더 건일 경우에는 순번을 `+1` 증가시키거나 `01` 번호로 자동 세팅하여 시스템 최적화 추천 번호를 UI 화면에 동적으로 생성해 주도록 아키텍처를 연동 완료하였다.

## 2. 발생한 기술적 오류 및 조치

- **오류 21**: CDS 뷰 인프라가 데이터베이스 내부의 압축된 로우 데이터(Raw Data) 구조를 표준 복원 연산 없이 ABAP 애플리케이션 레이어로 곧바로 다이렉트 스트리밍해 오면서, ALV 출력 화면상에서 자재이동문서 기준 원화(KRW) 필드 금액만 실제 수치보다 100배 축소되고 소수점이 비정상적으로 밀려 출력되는 자릿수 왜곡 정합성 오류가 발생하였다.
- **조치 21**: 프로그램 소스 코드 단에서 임시방편으로 100을 곱해주는 파편화된 우회 연산 방식을 배제하고, 데이터의 근본 원천인 CDS 뷰 정의 수식 내부에서 원화 금액 필드 컬럼에 명시적으로 `* 100` 수식을 내장 조치하였다. 이후 `cast` 구문을 사용하여 표준 통화 데이터 타입으로 강제 형 변환을 단행한 뒤, `@Semantics` 어노테이션 속성에 명확히 `KRW` 통화 키를 매핑하여 소수점이 원화 규격에 맞게 닫히도록 근본적인 정합성을 일치시켰다.

- **오류 22**: CDS 뷰 아키텍처 내부에서 외화 총액(`WRBTR`)을 수량(`MENGE`)으로 나누는(/) 산술 나누기 연산을 수행할 때, 연산 결과물 데이터 타입이 부동소수점(`FLTP`) 규격으로 시스템 자동 처리되면서 2진수 근사치 연산 한계가 도출되었다. 이로 인해 선적입고 외화(USD) 단가 데이터가 $75.59와 $76.00 사이의 임의 구간에서 제멋대로 반올림되거나 들쭉날쭉 가변되는 금액 왜곡 결함이 식별되었다.
- **조치 22**: 2진수 연산으로 발생하는 소수점 유실 오차를 원천 봉쇄하기 위하여 정확한 10진수 연산 타입인 `DEC` 속성으로 데이터 타입을 1차 변환 선언하였다. 이어서 CDS 내부 내장 특수 펑션인 `division` 연산식을 적용하여 소수점 자릿수를 유연하게 고정해 주었으며, OData 및 ABAP 통신 규격에 맞는 `CURR` 타입으로 최종 `cast` 형 변환을 완료하여 단가 정합성 불일치 결함을 완벽히 해결하였다.

- **오류 23**: 현업 사용자의 액션에 의해 화면 모드(`gv_mode`)가 가변 전환될 때 동일한 인터널 테이블 버퍼를 상호 공유하면서 필드카탈로그 데이터 세팅 사양만 바꾸어 데이터를 화면에 불러오도록 설계하였으나, 런타임 환경에서 화면 모드가 바뀌어도 ALV 필드 구조 레이아웃이 즉각 업데이트되지 않은 채 과거 스크린 구조에 그대로 고정되어 머물러 있는 화면 갱신 불능 결함이 발생하였다.
- **조치 23**: 화면 모드 전환 시 단순히 내부 인터널 테이블 데이터만 리프레시해 주는 방식으로는 ALV 컨트롤러가 인스턴스화된 필드 카탈로그 구조의 가변 변화를 감지하지 못함을 발견하였다. 이에 변경된 필드카탈로그 구조체 정보를 ALV 개체에 물리적으로 다시 동동기화시켜 주기 위하여, 레이아웃 변경 직후 `set_frontend_fieldcatalog` 표준 인스턴스 메서드를 소스코드 라인에 명시적으로 적용 및 호출해 줌으로써 화면 구조가 실시간으로 정합성 있게 리프레시 갱신되도록 조치하였다.

- **오류 24**: 스크린 페인터 레이아웃 툴에서 잔액 변수 필드(`GV_BALANCE`)의 음수 부호 표현 속성인 `WITH SIGN` 체크 옵션이 실수로 누락되어, 연산 잔액 결과 수치에 마이너스(`-`) 부호가 걸리는 특이 케이스 발생 시 예외 없이 시스템이 쇼크를 일으키며 쌩 덤프(Dump) 에러를 뿜어내는 심각한 결함이 확인되었다. 아울러 사용자가 입력 필드 자릿수를 초과하는 과도하게 거대한 외화 수치를 무작위 기입할 시 환율 변환 연산 과정에서 데이터 변수 자릿수 한도 임계치를 넘어서며 프로그램이 다운되는 리스크가 공존하였다.
- **조치 24**: 스크린 페인터 속성 레이어 단에서 `GV_BALANCE` 필드의 `WITH SIGN` 활성화 옵션을 명시적으로 체크해 주어 음수 데이터 유입 시 발생하는 시스템 덤프 에러를 완벽히 소거하였다. 또한 프로그램 내부에 `calculate_invoice_balance` 전용 연산 서브루틴을 신설하여 마이너스 금액 입력 시 화면 단에서 원천 차단 팝업을 띄우도록 가동하였고, 현재 환율 데이터를 기준으로 런타임상 입력이 허용되는 기술적 최대 USD 한도 수치를 사전에 역산하여 리스크 입력 자체를 원천 거부하도록 코드를 보완함으로써 프로그램의 런타임 안정성을 전면 확보하였다.
