## 2. 발생한 기술적 오류 및 조치

- **오류 1**: 자재이동문서 기준 원화 필드 금액 축소 오차 — CDS 뷰가 DB 내부의 압축된 raw 데이터를 복원 없이 ABAP 단으로 곧바로 읽어오면서, ALV 화면에서 자재이동문서 기준 원화 필드만 100배 축소되고 소수점이 잘못 출력되는 자릿수 왜곡 정합성 오류 발생
- **조치 1**: 임시 우회 연산 대신 데이터 원천인 CDS View 수식에서 원화 필드에 명시적으로 100을 곱하고 cast로 표준 통화 타입을 강제한 뒤, @Semantics 어노테이션으로 KRW 속성을 지정하여 근본적으로 해결
- **오류 2**: 선적입고 외화(USD) 단가 부동소수점 연산 오류 — CDS 뷰에서 나누기(/) 연산 시 결과물 타입이 부동소수점(FLTP)으로 자동 처리되면서, 2진수 근사치 계산 한계로 인해 외화 단가가 75.59와 76.00 사이에서 제멋대로 반올림되거나 들쭉날쭉 변하는 금액 왜곡 현상 발생
- **조치 2**: 소수점 오차를 막기 위해 정확한 10진수 타입인 DEC로 타입을 변환한 뒤, CDS 내부 내장 펑션인 division 연산으로 자릿수를 고정하고 CURR 타입으로 최종 cast하여 단가 정합성을 일치시킴
- **오류 3**: 화면 모드 변경 시 ALV 필드카탈로그 미갱신 현상 — 화면 모드(gv_mode)에 따라 동일한 인터널 테이블을 공유하면서 필드카탈로그 세팅만 바꾸어 데이터를 불러왔으나, 화면 전환 시 ALV 필드 구조가 곧바로 업데이트되지 않고 기존 화면에 머물러 있는 현상 발생
- **조치 3**: 데이터 리프레시뿐 아니라 변경된 필드카탈로그를 구조적으로 다시 동기화해줘야 함을 파악하고, set_frontend_fieldcatalog 메서드를 소스코드에 명시적으로 적용하여 화면을 실시간으로 갱신시킴
- **오류 4**: 잔액 계산 시 스크린 덤프 및 자릿수 오버플로우 오류 — 스크린 페인터에서 잔액 필드(GV_BALANCE)의 음수 부호 속성(WITH SIGN)이 누락되어 계산 값에 마이너스가 걸릴 때 SHORT DUMP가 발생했고, 사용자가 지나치게 큰 외화 금액을 입력할 시 환율 연산 과정에서 변수 자릿수 한도를 초과해 프로그램이 터지는 리스크가 존재함
- **조치 4**: 스크린 페인터에서 WITH SIGN 속성을 활성화하여 음수 덤프를 해결했고, calculate_invoice_balance 서브루틴을 신설하여 음수 입력 차단, 현재 환율 기준 입력 가능한 최대 USD 한도 사전 역산 및 차단 로직을 추가하여 프로그램 안정성을 확보함
