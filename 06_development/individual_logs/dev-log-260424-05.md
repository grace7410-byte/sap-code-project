## 1. 진행 내역
- **04.20 (판매 출고 로직 구현 및 참조 ALV 연동)**
  - 판매전표관리 프로그램 개발에 착수하여 판매 시 출고 로직 부분을 먼저 빌드하기 시작하였다.
  - 참조문서번호에 자재이동문서번호를 입력하고 조회하면 우측에 Reference Table ALV가 나타나며, 해당 행을 더블클릭 시 좌측 헤더 전표 영역에 필수 데이터만 자동 입력되도록 구상하였다. 수동 전표 생성이지만 사용자의 편리성을 위해 이 기능을 반영하였다.
- **04.21 (UI 흐름 및 데이터 바인딩 방식 최종 결정)**
  - 기존에는 사용자에게 흐름을 보여주기 위해 참조문서번호에 자재이동문서번호 조회 시 비활성되어 있던 헤더 전표 영역이 활성화되었다. 동시에 우측 Reference ALV에 관련 단계(출고, 송장청구, 입금)에 맞는 헤더와 아이템을 통합하여 보여주고, 이를 더블클릭하면 전표 작성이 편리해지도록 데이터를 바인딩하였다.
  - '입력확정' 버튼을 누르면 비활성화되며 임시 헤더 저장소 ALV로 이동하는 방식을 헤더와 아이템 모두에 적용하려 했으나, 데이터를 두 번이나 클릭해야 해서 사용자가 헷갈릴 수 있다고 판단하였다.
  - 이를 개선하기 위해 조회를 하자마자 헤더 영역에 전표 필수 데이터가 즉시 입력되도록 하고, 사용자가 직접 채워야 할 텍스트 입력창만 활성화되도록 구조를 바꿨다. 이후 화면에 함께 띄워진 Reference ALV를 더블클릭하여 아이템 전표를 생성하는 방식으로 최종 결정하였다.
- **04.22 (타 모듈 데이터 로드 및 송장청구 분석)**
  - 판매 출고 단계에서 SD, MM, CO 모듈의 테이블에서 계정과목과 문서번호 매출원가 금액 등을 호출하는 작업을 수행하였으며, 데이터 로드에 시간이 많이 소요되었다.
  - 다음 단계인 송장청구 시점에서 데이터를 어떤 방식으로 인터페이스해 와야 할지 아키텍처 모델링을 고민하였다.
- **04.23 (조정계정 반영을 위한 다중 조인 CDS View 설계)**
  - CDS View를 빌드하여 판매 시 출고 전표에 알맞은 데이터를 가져오도록 구현하였으며, 이를 송장청구 시점에도 동일하게 적용하고자 했다.
  - 다만 자재이동문서 헤더/아이템 테이블을 엮어 CO 매출원가와 출고 수량을 계산하던 기존 방식과 달리, 송장청구 단계에서는 RECON(조정계정)을 통한 접근이 필수적이었다.
  - 이를 해결하기 위해 각 테이블 간 조인을 걸어둔 2개의 선행 CDS View를 기반으로, 상위에서 전체를 묶어주는 통합 CDS View 설계를 진행하였다.
- **04.24 (출고 데이터 중심 프로그램 선행 구현 및 예외 처리)**
  - 복잡한 구조의 CDS View를 설계하는 데 예상보다 많은 시간이 소요되어 프로그램 전체 진척도 확보를 위해 개발 우선순위를 조정하였다. 먼저 안정화된 '판매 시 출고 단계'의 데이터를 기준으로 프로그램 구현을 선행하였다.
  - 참조문서번호에 원하는 자재이동문서번호(출고)나 청구문서번호(송장)를 넣고 라디오 버튼 체크 후 조회하면, 헤더 전표 영역에 필요한 값이 자동 입력되고 입력 오류를 방지하기 위해 해당 인풋창은 비활성 상태를 유지하도록 제어하였다.
  - 동시에 Reference ALV에 헤더와 아이템 정보가 통합된 CDS View를 출력하며, 이를 더블클릭하면 아이템 전표 생성 ALV로 헤더 데이터가 연동되어 들어가고 사용자는 나머지 미입력 값만 채우도록 구현하였다.
  - 최종전표검토 버튼 클릭 시 팝업으로 생성된 전표를 보여주고, '수동전표생성'을 누르면 DB 테이블에 최종 적재되도록 설계하였다. 또한 참조문서번호에 대응하는 각 테이블을 DB View에서 CDS View로 전환하였고, 공통 필드 카탈로그 구조를 공유하되 데이터 값만 동적으로 변경되도록 효율화하였다. 추후 취소 프로세스 처리를 위한 역분개(Reversal) 로직까지 고려하여 마무리를 진행 중이다.

## 2. 발생한 기술적 오류 및 조치
- **오류 1**: 필드 카탈로그 빌드 시 파라미터 설정 구문 규칙 오류로 인해, 지정된 명세보다 더 많은 파라미터가 필요하다는 시스템 에러가 발생함.
- **조치 1**: 매크로 및 선언 로직 내부의 각 파라미터를 점검하여 끝자리 구분 기호인 콤마(`,`)가 누락되거나 오입력된 부분을 정확히 보정 완료하였으며, 불필요하게 리소스가 낭비되는 문제를 해결함.
- **오류 2**: ALV 그리드에서 행 더블클릭 이벤트가 발생한 후, 추출된 전표 데이터를 메인 스크린 화면의 인풋창 상에 실시간으로 반영·표시하지 못하는 현상이 발생함.
- **조치 2**: `CL_GUI_CFW=>SET_NEW_OK_CODE` 메서드를 핸들러 내부에 도입하여 강제적으로 PAI(Process After Input) 이벤트를 타도록 트리거링함으로써 화면 새로고침 및 데이터 매핑 프로세스를 정상화함.
