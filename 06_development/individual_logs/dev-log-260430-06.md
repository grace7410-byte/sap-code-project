## 1. 진행 내역
**[ ZRB1FI0001 ]** 전표대시보드 프로그램

- 증빙일, 전기일, 회계연도에 들어갈 수 없는 잘못된 날짜 입력 시, 예외 메시지가 출력되도록 하였다.
- 헤더에 있는 참조번호 핫스팟 클릭 시, 참조한 문서의 상세 내용이 popup으로 출력되도록 구현하였다.
- 구매전표관리 버튼 클릭 시 구매전표 관리 프로그램으로 네비게이션 이동되도록 처리하였다.
- 구매전표관리 프로그램에서 전표 디비에 저장 후 전표대시보드 프로그램으로 복귀 시 데이터가 자동 반영되도록 연동하였다.

**[ ZRB1FI0002 ]** 구매전표관리 프로그램
- 부분전표 생성을 방지하기 위해 레퍼런스 테이블에 있는 행을 더블클릭 시, 기존에 해당 행의 차/대변 총 2줄씩 추가할 수 있었던 구조에서 한 행만 클릭해도 모든 행의 차/대변이 일괄 추가되도록 로직을 변경하였다.
- 선적입고, 송장, 플랜트 입고 시 발생하는 전표 중 FI 쪽에 생성되지 않은 문서들을 확인하여 생성할 수 있도록 참조문서번호로 조회 시 서치헬프(Search Help)를 설정하였다.
- 서치헬프 작동 프로세스에 연동되어 동적 제어를 수행하는 function module을 구성하였다.
- 헤더적요 미입력 상태인 경우 레퍼런스 테이블 더블클릭이 불가하도록 차단 처리하고 안내 메시지를 출력하였다.
- 최종 전표 예시 버튼 클릭 후 최종 예시를 확인하고 전표생성버튼 클릭 시, DB 테이블에 헤더와 아이템 레코드가 각각 insert 되도록 구현하였으며 이때 회계전표번호는 number range를 사용하여 순차 번호가 부여되도록 처리하였다.
- 전표 DB 테이블에 저장할 때 이미 마이그레이션 및 적재가 완료된 전표인 경우 채번 불가 처리 및 예외 메시지를 띄우도록 제어하였다.
- 레퍼런스 행 더블클릭을 통해 아이템 ALV에 데이터가 추가된 이후, 중복 추가를 시도하면 불가 처리 및 경고 메시지가 출력되도록 로직을 강화하였다.
- 데이터 누락 방지를 위해 헤더 적요 미입력 시 메시지 처리 및 전표 미저장 종료 시 안내 메시지 처리 로직을 구현하였다.

## 2. 발생한 기술적 오류 및 조치
- **오류 1**: 라디오버튼 선택 상태에 따라 참조문서번호 서치헬프에 매핑하여 사용하는 소스 테이블이 달라져야 하는데, 런타임 시 라디오 버튼의 활성화 값을 프로그램이 정상적으로 인식하지 못하는 현상이 발생함.
- **조치 1**: 필드 심볼(Field Symbol)을 할당하고 활용하여, 메인 프로그램 내 스크린 오브젝트인 라디오버튼의 선택 값을 실시간으로 바로 바라보고 인식할 수 있도록 동적 구조를 구성하여 해결함.
- **오류 2**: 참조문서번호 서치헬프 구성 시 회계(FI) 전표에 아직 생성 및 등록되지 않은 미처리 번호들만 필터링하여 동적으로 화면에 가져와야 하는 요건 구현에 어려움이 발생함.
- **조치 2**: 서치헬프 오브젝트 데이터 추출 쿼리의 WHERE 조건절에 `NOT IN` 구문을 명시적으로 사용하여, 이미 기존 전표 헤더 테이블에 적재 완료된 번호들을 차집하여 제외하고 매핑이 없는 유효 번호만 추출되도록 필터링 조치함.
