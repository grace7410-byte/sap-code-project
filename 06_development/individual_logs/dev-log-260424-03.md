  - 전사 프로세스 통합 설계의 일환으로 PO(구매), SO(판매), PrO(생산) 등 모든 입/출고 시 부피 실측값을 관리할 수 있는 아키텍처를 수립하고, 내부 CASE 문을 통해 문서 유형을 '프로세스-이동구분-단계' 3단 구조로 분리하였다.
  - FIELD-SYMBOL을 활용하여 선적입고, 실측입고 등을 세분화함으로써 데이터 오입력을 방지하였다.
- **04.22 (화면 전환 로직 및 오더 통합 설계 기초 - 200번 ALV 기본 틀 설정)** `(최종: 모듈풀 -> 리포트 프로그램 전환되며 100번 Screen으로 변경)`
  - LEAVE TO SCREEN을 사용하여 메모리 스택 누적을 방지하고, 프로그램 간 이동 시 시스템 부하를 최소화하였다.
  - 부피 측정에 필요한 구매, 판매, 생산의 각기 다른 필드를 하나의 ALV에서 통합형으로 관리하고, 측정 문서를 동시 '생성'하기 위해 공통 itab 및 통합 Field Catalog를 설계하였다.
- **04.23 (전사 통합 부피 측정 프로세스 구현 - SD 연동, 200번 ALV 구현)** `(최종: 모듈풀 -> 리포트 프로그램 전환되며 100번 Screen으로 변경)`
  - VBELN(판매오더) → ZDOCNO(통합문서번호), POSNR(항목) → ZDOCIT 등 각 모듈의 필드를 통합 구조에 맞게 매핑하여 CORRESPONDING FIELDS로 데이터 추출 로직을 구현하였다.
  - 구매/판매/생산 오더와 실제 부피 측정 테이블([ZTB1MM0020](../../04_design/table_specifications/01_MM_table_spec.md#ztb1mm0020))을 LEFT OUTER JOIN 하여 측정 전/후 데이터를 한 화면에서 모니터링할 수 있도록 구현하였다.
  - 실측 수량(ZAVOL)과 환산 수량(ZSVOL) 필드를 구분하고 각각의 단위(MEINS_2, MEINS_3)를 독립적으로 관리하여 향후 온도/밀도 보정 계수 계산을 위한 데이터 기반을 강화하였다.
- **04.24 (VCF 보정 로직 설계 및 사용자 인터페이스 연동 - 220번 서브스크린, 200번 로직 구현)** `(최종: 모듈풀 -> 리포트 프로그램 전환되며 110번 Subscreen으로 변경)`
  - ICON 필드를 활용하여 측정 완료 여부와 입/출고 프로세스 두 가지 필드를 직관적으로 시각화하였다.
  - ALV 행 더블클릭 시 POPUP_TO_CONFIRM을 호출하여 선택한 오더 정보를 서브스크린으로 전달하도록 구성하였다.
  - 자재 코드(MATNR)만으로는 식별이 어려운 점을 개선하기 위해 자재 텍스트 테이블 [ZTB1MM0002](../../04_design/table_specifications/01_MM_table_spec.md#ztb1mm0002) 테이블을 조회하여 자재명(MAKTX)을 실시간으로 화면에 바인딩하였다.
  - 온도(15 CEL 표준) 및 밀도에 따른 열팽창계수(alpha)를 적용하여 실측 부피와 환산 부피 간의 상호 변환(VCF) 로직 수학적 모델링을 완료하였다.

## 2. 발생한 기술적 오류 및 조치
- **오류 1**: 자재 코드 입력 시 연관 필드(단위, 단가 등)를 자동 채우는 과정에서 리프레시와 이벤트가 충돌하여 '무한 루프' 및 '행 생성 오류' 발생.
- **조치 1**: HANDLE_DATA_CHANGED 내에서 변경된 셀만 정밀 조정하여 값을 업데이트하고, 불필요한 전체 리프레시를 없애 WTI 잔상 등을 제거하여 조치 완료.
- **오류 2**: 200번 화면에서 BACK 클릭 시 100번의 자동 점프 로직이 재실행되어 화면이 갇히는 무한 루프 발생.
- **조치 2**: 사용자 복귀 플래그(gv_back)를 도입하여 의도적인 화면 복귀 시에는 파라미터 체크 로직을 타지 않도록 제어하여 프로세스 정상화 완료.
- **오류 3**: 200번 화면 조회 버튼 클릭 후 현재 화면이 유지되지 않고 종료되는 현상 발생.
- **조치 3**: 스크린의 Next Dynpro 속성을 현재 화면 번호(200)로 지정하여 PAI 이후에도 조회된 데이터가 유지되도록 구조 수정 완료.
