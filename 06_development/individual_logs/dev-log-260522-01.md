## 1. 진행 내역

**[ ZB1MM_YSSCURRENCY / ZB1MM_YSSMOPS_CSV ] 외부 API 연동 및 재고 현황 관리 파이프라인 구축 (구현중)**

* **환율 API 조회 및 배치 자동화를 통한 환율 마스터 테이블 업데이트**
    * 외부 금융 시스템과의 실시간 데이터 동기화를 위하여 ABAP 내부에서 엔드포인트 전용 HTTP REQUEST 객체를 생성하였으며, 규격에 맞는 헤더 구성 후 대상 시스템에 원천 데이터(DATA) 요청을 트리거하였다. 
    * 호출 완료 후 응답 플로우로 수신된 JSON 포맷의 파일 데이터를 ABAP 오픈 파서 알고리즘을 통해 스트리밍하여 내부 인터널 테이블(INTERNAL TABLE)에 정교하게 파싱 및 삽입 처리하였다. 적재된 다국적 통화 원천 데이터 중에서 핵심 지표인 미국 달러(USD)에 해당하는 레코드 레이어만 필터링하여 시스템 표준 환율 마스터 데이터베이스 테이블에 최종 반영 및 삽입하였다.
    * 상기 개발 완료된 환율 및 국제유가 인터페이스 프로그램을 매일 특정 시점에 수동 조작 없이 백그라운드에서 가동할 수 있도록 SAP 표준 배치 프로그램 환경을 구축 및 연동 실행하였다. 가동 직후 가시성 확보를 위해 `WRITE` 구문을 확장 적용하여 배치 트랜잭션 수행 결과 세부 메시지를 시스템 내부 SPOOL 데이터 테이블에 실시간 보관 및 삽입 처리하였다.
* **국제유가 다운로드 인터페이스 링크를 활용한 유가 마스터 조회 및 테이블 관리**
    * 글로벌 유가 지표를 시스템 내부에 전사 반영하기 위하여, 수립된 HTTP REQUEST 메커니즘에 `REQUEST_HEAD` 필드 속성 및 필수 전송용 `PAYLOAD` 데이터를 인코딩하여 외부 다운로드 링크 세션에 데이터 요청을 전달하였다.
    * 네트워크 인터페이스를 거쳐 스트림 문자열(String) 구조로 유입된 로우 데이터를 수신한 뒤, ABAP의 `SPLIT` 구문 및 가변 분리자를 적용하여 제품 종류별 유가 명세 정보로 쪼개어 가공하는 조회 로직을 최적화하였다. 정돈된 세부 제품별 유가 레코드를 1차 인터널 테이블에 안전하게 격리 삽입한 뒤, 최종 마스터 아카이브인 전용 국제유가 테이블 데이터베이스에 정합성 있게 인서트(Insert) 처리하였다.
* **표준 자재이동 문서 흐름 관리를 위한 재고 현황 관리 원장 테이블 데이터 트랜잭션 동적 구현**
    * 정유 제조 비즈니스 공정 단계별로 재고 수량, 총평가금액, 총평가단가가 각기 상이한 규칙과 가변 매핑 구조에 의해 유기적으로 변화하는 로직을 하나의 범용 펑션 모듈(`FUNCTION MODULE`) 인프라 내에 완전 통합하여 구현하였다.
    * 자재 문서 번호(`MBLNR`) 수치를 입력 파라미터(`INPUT`)로 수신하는 구조를 매핑하였으며, 해당 트랜잭션을 기반으로 자재 마스터 테이블(['ZTB1MM0001'](../../04_design/table_specifications/01_MM_table_spec.md#ztb1mm0001)/['ZTB1MM0003'](../../04_design/table_specifications/01_MM_table_spec.md#ztb1mm0003)), 실시간 자재 재고량 테이블(`MARD`), 그리고 전용 재고 현황관리 헤더 및 아이템 테이블 전반에 걸쳐 레코드 상태 값이 실시간으로 일관성 있게 업데이트 및 변동되도록 데이터 흐름 인터커넥션을 구현하였다.

## 2. 발생한 기술적 오류 및 조치

- **오류 01**: 글로벌 유가 데이터 수집을 위해 제공된 외부 다운로드 인터페이스 링크로부터 HTTP 바이너리 스트림 형태의 XLS 확장자 파일을 수신하였으나, ABAP 프로그램 단에서 해당 원천 파일 바이너리를 텍스트 기반 문자열 데이터로 원활하게 변환·디코딩하지 못하여 인터페이스 연동이 중단되는 결함이 발생하였다.
- **조치 01**: 인코딩 변환 호환성 리스크가 있는 기존 XLS 원천 파일 포맷 대신, 경량화된 표준 텍스트 통신 규격인 CSV 파일 포맷 형식의 전용 다운로드 데이터 공급 링크로 아키텍처를 스위칭 및 대체 지정하였다. 이를 통해 수신 레이어에서 별도의 복잡한 바이너리 변환 레이징 필터 없이 곧바로 가독성 높은 순수 문자열(String) 데이터셋으로 완벽하게 파싱 변환하여 내부 데이터 무결성을 유지하였다.
