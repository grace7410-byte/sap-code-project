## 2. 기술적 트러블슈팅
### 이슈 1: 판매 단계 1:N 분개 로직 처리 및 데이터 소스 정합성 문제
- **현상**: 초기 1:1 대응 방식의 FM 설계가 실제 판매 제품 출고 시 발생하는 차변(매출원가)과 대변(다수 제품)의 1:N 관계를 수용하지 못함
- **원인**: 단일 제품 기반의 로직 설계 오류 및 SD 모듈 데이터만으로는 정확한 매출원가 산출에 한계가 있음
- **해결**: 
    1. 내부 테이블을 활용하여 다중 아이템을 처리할 수 있도록 FM 로직을 1:N 구조로 전면 수정
    2. 금액 산정 시 SD 테이블 대신 CO(원가) 모듈의 데이터를 참조하도록 인터페이스 데이터 소스 변경

### 이슈 2: 프로그램 간 데이터 전달 시 사용자 편의성 미흡
- **현상**: 대시보드에서 이동 시 데이터를 매번 재입력해야 하는 번거로움 발생
- **원인**: 프로그램 간 파라미터 전달 및 화면 속성 제어 로직 부재
- **해결**: `EXPORT/IMPORT` 메모리 ID 또는 `SET/GET PARAMETER`를 활용하여 데이터를 전달하고, 전달받은 값의 유무에 따라 `LOOP AT SCREEN`을 통해 인풋창을 동적으로 제어(활성/비활성)함
