# 모듈 간 고급 인터페이스 및 트랜잭션 정합성 명세

**최종 수정일**: 2026-04-23  
**상태**: 확정 (Approved)  
**관련 컴포넌트**: MM (구매/재고), LE (물류/운송), PP (생산), FI (재무회계)

---

## 1. 개요 (Overview)
본 문서는 구매, 물류, 생산, 회계 모듈 간의 고급 인터페이스 연동 구조를 다룹니다. 각 프로세스 발생 시 데이터 단절을 해소하고 트랜잭션 무결성을 보장하기 위한 핵심 로직을 정의합니다.

---

## 2. 모듈별 인터페이스 상세 로직

### [MM-LE-FI] 서비스 PO 생성 설계 및 데이터 흐름 인터페이스

* **PO 생성 및 참조 시점 제어**
  - PO가 생성되는 시점에 가저장 플래그(`GV_SAVE_CHECK = 'X'`)가 활성화되며, 이때 데이터는 DB가 아닌 내부 인터널 테이블(ITAB)에만 임시 저장됨.
  - 이때 발행된 구매오더 문서번호(`GV_EBELN`)를 채번하여 향후 서비스 오더의 '참조 문서 번호'로 구조적 연결 설정을 진행함.

* **공급업체 변경 및 데이터 검증 (PAI)**
  - 공급업체(Vendor) 변경 후 엔터(ENTER) 이벤트 발생 시 동적 밸리데이션 체크 로직 가동.
  - 공급업체 변경 시 해당 공급업체가 속한 국가코드 목록 기반의 BP(Business Partner)만 화면에 보이도록 Search Help(조회 도움말) 제한 설정. (별도로 지정된 국가코드를 기반으로 필터링되어 조회되도록 셋팅)
  - 엔터 입력 시, 사전에 정의된 국가코드와 상이할 경우 시스템 아키텍처 상 장부 정합성을 위해 즉시 에러(Error Message)를 발생시키고 프로세스를 블로킹함.

* **화면 동적 제어 (UX/UI)**
  - 공급업체 확정 시 구매조직, 구매그룹, 회사코드, 지급조건 데이터가 백엔드 로직에 의해 자동으로 변경 및 매핑됨.
  - 현재 화면에서 불필요한 '최적화 데이터' 및 '수율 차트' 버튼은 동적으로 숨김(`Active = 0`) 처리함.
  - 관련 TEXT 번호를 SCREEN 내에 하드코딩 없이 동적 바인딩하며, 안내 SCREEN을 통해 서비스 오더 생성 프로그램 가이드를 확인할 수 있도록 구현함.

* **동적 탭스트립(Tabstrip) 생성 및 PBO 제어**
  - 화면을 그리는 PBO(Process Before Output) 시점에 펑션 및 클래스의 `CREATE OBJECT`가 호출될 때, `GV_SAVE_CHECK = 'X'` 상태인지를 최우선 검증함.
  - 해당 조건이 충족될 경우 화면 하단에 서비스 아이템 데이터를 입력할 수 있는 서브 스크린 영역을 동적으로 활성화함.
  - 서브 스크린 내에 **"서비스"**, **"경로"** 2개의 탭스트립을 생성하여 서비스 아이템 데이터와 실시간 운송 현황 데이터를 입력받을 수 있는 인터페이스 제공.

* **탭스트립 세부 데이터 연동 로직**
  - **[서비스] 탭**: 기존 일반 PO의 가저장 금액 정보를 메모리에서 실시간으로 읽어와 연동하고, 서비스 아이템 데이터 세부 내역을 불러옴.
  - **[경로] 탭**: 국가 코드별 운송 경로 마스터 테이블을 기반으로 셋팅하되, 성능을 위해 CDS View를 활용하여 BP 코드와 조합 서치 후 자동으로 운송 경로를 레이아웃에 뿌려줌.
  - 국가 코드를 기반으로 운송 마스터 데이터(Lead Time 등)를 소싱하며, 시작 날짜는 현재 시스템 날짜(`SY-DATUM`)를 기준으로 자동 인입함.
  - 물류 예측 정합성을 위해 '운송 요청 날짜'를 기준점으로 삼고, 마스터에 정의된 각 운송 경로별 소요 일수(Days)를 계산식으로 더하여 최종 도착 예정일을 자동 연산함.

* **트랜잭션 무결성 (All or Nothing)**
  - 종속적인 인터페이스 아키텍처 구조상, 하단의 **서비스 PO 데이터까지 완벽히 생성 및 승인되어야만** 기존의 일반 PO와 함께 최종 DB 테이블에 커밋(Commit) 및 인서트 처리됨.
  - 만약 사용자가 프로세스 중간에 취소(Cancel)를 누르거나 화면을 이탈할 경우, ITAB에 임시 적재되었던 데이터와 기 생성 플래그가 맺혔던 기존 PO 데이터까지 통째로 **롤백(Rollback)**되어 동시 소멸함.

### [MM-PP] 생산 확정 기반 부피측정 및 입고 프로세스 연동
* **연동 개념**: PP 생산계획/오더 테이블의 오더량을 매핑하여 MM 부피측정 프로그램의 기준값으로 활용.
* **데이터 전제 조건**: 정유 공정 특성상 오더량과 실제 확정량이 상이할 수 있으나, 현재 시점에서는 공정 가동 전 인입 데이터인 '오더량'을 최종 확정량으로 간주하여 입고 데이터와 정합성을 매핑함.
